# 机器人能力

按 SKILL.md 的编号定位章节，只读本次需要的章节及本节 C00。每项能力依次给出选择、前置、示例、成功标准和失败处理；不要跳过同一能力的第二种调用。

## C00 所有示例的共同前提

- 除明确标注“异步入口”的代码外，所有 Python 片段放在开发步骤 D04 的 `do_work(app)` 内；其中 `robot = app.robot`，不能在全局自行创建连接。
- 先按 D03 检查实际 SDK 方法，再在连接后检查本章列出的 capability。示例中出现 `your_*_id` 是待配置项，不是真实 ID，查明后才能运行。
- `timeout`、`duration`、`sleep` 一般用秒；`*_ms` 用毫秒；角度用度；宽高用像素；音频采样率用 Hz。保留每个代码块的参数注释。
- `app_support.py` 由准备工具复制到项目；已有应用从模板复制这个文件。`device_session` 只用于本应用独占调度的资源：启动成功或应答超时后执行清理，明确拒绝启动时不停止其他所有者。清理失败会记录异常，不能据此宣称设备已停。
- 保留 `with` 和 `finally`。等待超时不代表设备已停止；不要只杀应用进程来代替清理；托管停止仍可能到期终止进程，见开发步骤 D06。
- 文件保存在运行应用的电脑；示例固定文件名用于演示，产品代码使用自己的输出目录和唯一文件名，避免覆盖照片或录音。
- 未收到真实结果时报告“未得到结果”，不要生成假 JPEG、假音频或模拟设备响应充当成功。

### 组合能力时的执行顺序

| 资源 | 默认组合规则 |
|---|---|
| 相机 | 拍照、跟踪、推理、视频录制、视频 RTC 先按串行执行，关闭上一会话再启动下一项 |
| 普通音频 | 独立麦克风与普通播放串行，先结束录音再播放回复 |
| RTC | audio 占麦克风和喇叭；video 占相机；av 同时占用，不拆成两个相互竞争的会话 |
| 屏幕 | 动画、作品、程序化表情由一个业务模块调度，不同时争抢显示 |
| 云台 | 跟踪期间先停止跟踪再执行手动运动，退出后释放本应用的运动任务 |

配套固件可支持音频 RTC 加普通拍照；是否有足够内存、是否支持具体组合仍需运行验证。上述表格是实现的默认顺序，不是宣称所有能力硬件上绝对互斥。

### 用现有能力组成应用

- 拍照助手：按钮 → C07 → 保存 JPEG → 本应用界面显示。
- 触摸宠物：C10 → C04 或 C03 → C02 → 回待机。
- 语音留言：C06 录 WAV → 释放麦克风 → C05 播放。
- 视觉提醒：C08 → 检查检测结果 → C02/C05；同一事件设置冷却时间，避免不断重复提醒。
- 聊天机器人：C16，修改提示词和业务；不要把录音接口称作 ASR。
