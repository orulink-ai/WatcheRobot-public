# C15 状态与任务

先读 [共同前提 C00](../机器人能力.md)。

**如何选择：** 先检查实际设备声明，再调用新能力；需要判断任务完成时读取 Job，而非仅看控制命令返回。

**使用前检查：** device_info/capabilities 为已接收信息。重连后 refresh_device_info 请求刷新；supports 仅判断声明，不执行能力。资源快照的接收时间和设备归属要一并看。

### 设备与资源信息

```python
# 读取当前缓存的设备身份和握手信息。
print(robot.device_info)
# 设备声明的能力集合；可用来决定显示哪些功能入口。
print(robot.capabilities)
# 检查某个能力标识，返回 True / False；不实际执行拍照。
print(robot.supports("camera.capture.feedback.v1"))

# 设备重连后刷新握手信息。
robot.refresh_device_info()
# 最近收到的资源快照；这是设备上报数据，不是每次访问都实时测量。
print(robot.resource_snapshot)
# 当前会话保存的资源基线，可用于前后比较。
print(robot.resource_baseline)
# RTC 相关的资源基线。
print(robot.resource_rtc_baseline)
# 已收集的资源快照历史，可观察资源随时间的变化。
print(robot.resource_history)
```

### 任务超时后请求取消

**函数片段，不会自动执行。** 调用点：在获取本次动作、动画或灯效的 `job` 后，使用 `wait_or_cancel(job)` 替换原来的 `job.wait(...)`；保留外层资源清理。

```python
# job 为动作、动画、音效、灯效或行为返回的任务句柄。
def wait_or_cancel(job):
    try:
        # 最多等待任务结果 10 秒；等待超时本身不会自动停止设备任务。
        job.wait(timeout=10)
    except TimeoutError:
        # 超时后显式请求取消；发送取消不等于设备已经完成停止。
        job.cancel()
        # 继续把超时异常交给调用方处理，避免误认为任务成功。
        raise
    # 依次输出任务 ID、状态、错误码和原因，便于记录与排查。
    print(job.id, job.state, job.error_code, job.reason)
```

### 仅排查资源问题时读取快照

需要诊断应用的资源占用时，再把 `robot.resource_evidence` 加入 sdk-requirements.json。它是属性，不加括号调用；普通应用不必加入这项检查。

```python
# 检查实际安装的 SDK 是否提供这个可选诊断属性。
if not hasattr(robot, "resource_evidence"):
    raise RuntimeError("当前 SDK 没有 resource_evidence")

# 一次读取快照与来源信息；打印缓存数据不会触发设备实时测量。
evidence = robot.resource_evidence
print("资源快照：", evidence.get("snapshot"))
print("来源设备：", evidence.get("device_id"))
# received_at 是主机单调时钟的秒数，不是日期时间戳。
print("接收时间：", evidence.get("received_at"))
```

快照不能证明设备当前在线。判断资源变化前，确认数据足够新、来源属于当前设备和连接；不要比较跨设备或跨连接的基线。

**成功标准：** 区分设备声明、命令 ACK、Job COMPLETED、实际媒体产物/硬件效果。资源历史只能证明已收到的上报。

**失败与清理：** Job wait 超时不会自动取消。记录 error_code/reason，正常成功与 CANCELLED/FAILED 分开。需要持续任务时保留句柄，退出时请求取消并观察结果，不无限等待。
