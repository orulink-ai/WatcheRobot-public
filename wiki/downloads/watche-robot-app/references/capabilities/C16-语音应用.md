# C16 语音应用

先读 [共同前提 C00](../机器人能力.md)。

**先选一种路线：**

| 用户需要 | 使用方式 |
|---|---|
| 自己选择 ASR、LLM、TTS，修改角色提示词 | `prepare --template voice`，默认安装最新正式 SDK，再配置云服务 |
| 设备已有可用 JoyInside，应用只需识别一句话或播放指定文本 | 普通触发模板加 `robot.speech`，见“复用设备语音” |

先检查实际安装报告中的 `cli.voice` 或 `speech.open`。录音接口本身不提供语音识别；设备 speech 也不替应用生成自己的 LLM 回复。需要服务申请教程时再读 [语音教程](../源码与资料.md)。

### 使用自选云服务

**使用前检查：** 本机 app init --help 必须支持 --template voice；还要有 app configure。当前源码默认组合为火山 ASR、通义 LLM、火山 TTS；安装包实际生成配置为准。用户需自己开通服务并在本机输入凭据。

**成功标准：** 用户说话 → 有有效识别文本 → LLM 回复 → 设备播放；再问上一轮问题，检查多轮上下文。凭据向导通过只证明本地配置有效，不代表云服务权限或真机链路通过。

**失败与清理：** 默认半双工：录音结束后释放麦克风，再生成并播放回复。不能承诺抢话打断、长期记忆或身份识别。更多行为在用户应用层开发，保持受管设备通道。

### 生成、配置与修改

按开发步骤 D02 使用平台入口 `prepare --project <新目录> --template voice`。工具先检查 cli.voice，再由官方 app init 生成语音目录；不要手写一个同名空壳。

进入生成目录，并使用其隔离环境的 CLI：

```text
watcherobot app configure
watcherobot app check .
watcherobot app run .
```

`configure` 是本机交互式凭据向导，输入不回显；不要让用户把 API Key 发到聊天。只配置一项时用 `app configure --service asr` / `llm` / `tts`。向导不自动开通云账号，不替用户购买资源。

文件修改位置：
- `prompts/system.md`：角色、语气和回答规则。
- `config/models/asr.toml`：识别服务；`llm.toml`：语言模型；`tts.toml`：合成服务和音色。三个文件分开保存。
- `config/persona.toml`：生成模板提供的角色配置，保持其现有字段结构。
- `credentials/asr.toml`、`llm.toml`、`tts.toml`：用户本机凭据，禁止提交和发布；优先通过 configure 填写。
- `application/voice.py`：应用的业务组装；`app.py` 保持官方受管入口。

模型配置使用 TOML，不是 app.json。`provider/model/voice_id/resource_id/base_url` 是字符串；`timeout` 是秒；`parameters/options` 为 TOML 表。顶层键必须在表标题之前。修改模型前检查供应商和账号实际支持的模型/音色，不能猜测模型 ID。

云端 ASR 会接收录音，LLM 接收对话文本，TTS 接收回复文本；选服务时向用户说明这些数据去向并按用户选择配置。不要默认保存原始音频、正文或密钥到日志。

需要自定义供应商时，生成项目中的 `application/voice.py` 负责注册适配器；公共接口从 `watcherobot.voice.contracts` 导入。ASR 接收 16 kHz 单声道 S16LE 的 `AsyncIterator[bytes]`，返回 `Transcript` 异步流；LLM 接收 `Message` 序列并返回文本异步流；TTS 返回 `AudioChunk` 异步流，播放前转为 24 kHz 单声道 S16LE。适配器实现异步 close。优先用模板已有供应商，只有用户要求扩展时才增加适配器。


### 复用设备语音

先在实际安装报告中确认 `speech.open`、`speech.close`、`speech_session.recognize`、`speech_session.say`。设备需声明 `speech.joyinside.v1`，并已保存可用的 JoyInside 配置；电脑不需要取得设备的 AK/SK。未配置时报告缺少条件，不自动改成其他云服务。

```python
from app_support import device_session

if not robot.supports('speech.joyinside.v1'):
    raise RuntimeError("设备未声明 speech.joyinside.v1")

with device_session(
    # timeout：等待设备语音会话就绪的秒数；会话独占麦克风和喇叭。
    lambda: robot.speech.open(timeout=30),
    robot.speech.close,  # 也能重试清理 open 超时后可能留下的本应用会话。
) as session:
    text = session.recognize(timeout=30)  # 等待最终识别文本，不是原始音频。
    # 在这里把 text 交给本应用的业务逻辑或 LLM；本例只播固定确认语。
    reply = "收到，我们开始吧。"
    session.say(reply, timeout=60)  # 等待设备实际播放收尾；秒。
# 不默认打印用户语音内容；退出时关闭本应用会话。
```

这是半双工：先 recognize，再 say；不与普通录音、播放或 RTC 并行。say 文本限 1–999 个 UTF-8 字节，不能空白或含 NUL。每会话最多 32 个请求，持续应用在预算用尽前关闭重开；识别和合成都计入请求。数据会发送到设备配置的 JoyInside 云服务。

取消在途请求可用本次 `session.cancel()`，完成或取消后仍要 close；close 超时则用 `robot.speech.close()` 重试本应用清理。SDK 会话属于连接时的设备，重连后不要复用旧句柄。这些等待可能超过 Runtime 的退出预算，持续应用必须设计停止路径并遵循 D06；不要把命令 ACK 当作识别/播放完成。
