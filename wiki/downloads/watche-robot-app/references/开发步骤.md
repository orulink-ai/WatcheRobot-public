# 开发步骤

新应用按 D01—D05 完成本地交付；已有项目从 D03 开始。真机运行读 D06，失败查 D07，用户要求发布才读 D08。

## D01 选择目录、解释器和模板

- 目标目录使用用户指定位置；未指定时使用当前工作目录。新项目目录必须不存在。
- 项目解释器要求 Python 3.10—3.12，优先 3.11。先查看本机已有解释器，缺少时准备兼容 Python；不要改全局默认版本或忽略包版本要求。
- `photo`：启动拍一张照片后结束；`input`：持续监听背部触摸并亮灯；`button`：本机网页按钮拍照并显示结果。替换业务时保留相应的单次、循环或按钮触发结构。
- 语音需求先读 C16：自选 ASR/LLM/TTS 用 `voice` 模板；复用设备已有 JoyInside 用普通触发模板加 `robot.speech`。

## D02 一个命令准备新项目

先把下方 skill 路径和项目路径替换为当前环境的绝对路径。两个入口参数相同：`prepare --project <目录> --template photo|input|button|voice`。默认从正式 PyPI 安装最新兼容稳定版 `watcherobot`，不固定版本；`--python` 可指定项目解释器，`--sdk` 用于用户明确指定的包版本、本地 wheel 或源码；默认无需此参数。

Windows PowerShell：
```powershell
& 'C:/skill所在目录/watche-robot-app/scripts/watche-app.ps1' prepare --project 'C:/应用父目录/my_robot_app' --template photo --python 'C:/Python311/python.exe'
```
macOS/Linux：
```sh
sh '/skill所在目录/watche-robot-app/scripts/watche-app.sh' prepare --project '/应用父目录/my_robot_app' --template photo --python '/Python311/bin/python3'
```

入口默认用系统 `python`（Windows）或 `python3`（POSIX）运行共用核心；核心要求 Python 3.10+。若这些命令不存在，可在本次命令环境中将 `WATCHE_PYTHON` 设置为已有解释器完整路径。`--python` 指定的是创建项目环境的解释器，不会替换系统 Python。

准备工具负责：检查目标目录 → 创建项目隔离环境 → 安装 SDK → 检查模板所需接口 → 官方 app init → 放入完整模板 → 本地检查。命令不启动 Daemon 或机器人。

退出码：0 成功，1 执行失败，2 参数错误；两平台相同。失败立即停止，保留 `skill-setup.json` 的失败状态和现场，不能继续声称准备完成。目标目录已存在时拒绝覆盖；修复安装问题后换一个新目录执行，已有应用用 D03。

## D03 查看结果或接入已有项目

新项目生成：`app.json`、`app.py`、`app_support.py`、官方配套文件、`.venv/`、`sdk-requirements.json`、`sdk-capabilities.json`、`skill-setup.json`。button 模板另带 `photo_app.py`；voice 使用官方目录结构。

- `sdk-capabilities.json`：记录实际解释器、SDK 路径/版本及手册接口签名是否兼容；`available: false` 的接口不能使用。它不代表固件支持或媒体效果。
- 语音应用需检查 `cli.voice`；使用资源诊断属性时检查 `robot.resource_evidence`。只处理本次应用需要的能力，不因报告中其他可选能力缺失而阻塞开发。
- `sdk-requirements.json`：本应用实际使用的接口名数组。例如普通拍照为 `["camera.capture"]`；要带反馈则改为 `["camera.capture_with_feedback"]` 并将模板 `WITH_FEEDBACK` 改为 True。
- 修改功能时，将实际调用的方法加入 requirements（名称从能力报告中复制），然后执行 check。“未登记接口合同”表示 Skill 尚未覆盖，不等于 SDK 不支持；核对官方源码/已安装对象并补充合同后重查。
- 这些检查文件中的本机路径不发布；工具已补充 `.gitignore` 和 `.watcherignore`。媒体输出也排除。

已有项目：读取原 app.json、入口和运行说明，沿用环境及依赖。不要 prepare，也不要覆盖入口。需要通用清理时复制本 skill 的 `assets/templates/app_support.py` 到合适的应用模块；创建 requirements 后，用 check 的 `--python <原解释器>` 指定现有环境。只有应用实际要改用本版 SDK 时才调整安装，不批量重装。

## D04 在明确位置添加行为

| 模板 | 修改位置 | 使用方法 |
|---|---|---|
| photo | app.py 的 capture_photo/run；保留 main 与 finish_thread | 运行后拍照，照片写入项目 photos 目录，每次唯一文件名 |
| input | app.py 的 listen 中事件匹配后的处理 | 持续等待 back_touch/press；单次等待超时继续，退出时结束循环并清理 |
| button | app.py 的 POST /capture 处理；拍照函数在 photo_app.py | 打开日志里的本机 URL，点击拍照；处理中禁用按钮，并发请求返回 409 |

所有例子都有实际触发入口，不把只定义函数当作功能已经运行。用户要求定时触发时沿用 input 的退出条件，将输入等待替换为可中断的有限等待；不要使用永久 sleep。

能力手册同步片段放到工作函数中，使用 `robot = app.robot`，保留对应 import 和参数注释。模板共用 `device_session(start, stop)`：本应用独占调度的资源启动成功或应答超时后执行停止；明确拒绝启动时不停止其他所有者。不要再把 start 放到清理范围之外。返回独立会话的接口按手册使用 with，录制启动超时的未知 ID 限制见资源与兼容。

只需一次通用同步任务时，可将 photo 的 run 换为以下形式；main 保持不变：
```python
from app_support import finish_thread

def do_work(app):
    robot = app.robot
    # 示例：只读能力；将本次能力章节的完整片段放在这里。
    app.logger.info("设备声明：%s", robot.capabilities)

async def run(app):
    if not app.shutdown_requested:
        await finish_thread(do_work, app, shutdown_requested=lambda: app.shutdown_requested)
```

设备超时/断线时记录真实错误，不自动重放有副作用命令。网页模板会显示错误并允许下次明确点击重试；输入模板遇到设备异常会退出并记录错误。增加第三方库时同时更新 app.json.dependencies 与项目环境，不将 watcherobot 填入 dependencies。

## D05 一个命令检查项目

Windows PowerShell：
```powershell
& 'C:/skill所在目录/watche-robot-app/scripts/watche-app.ps1' check --project 'C:/应用父目录/my_robot_app'
```
macOS/Linux：
```sh
sh '/skill所在目录/watche-robot-app/scripts/watche-app.sh' check --project '/应用父目录/my_robot_app'
```

check 使用项目自己的 Python，检查 Python 语法、pip 依赖、官方 app check 和 requirements 中的方法签名，生成兼容报告；不会执行用户 app.py。已有环境可加 `--python <路径>`；临时核查某个可选能力可加 `--require camera.capture_with_feedback`，但正式代码仍需把它写入 requirements。

成功要求退出码为 0。静态检查不会替代函数逻辑、设备与媒体验证：检查本应用的成功、超时、取消、重复触发路径；还要搜索未替换的 `your_*_id`。没有机器人时到此完成本地交付，说明待实机验证；不得伪造 Daemon 凭据或返回假媒体。

## D06 设备连接与托管运行

以下 `watcherobot` 是命令简写，执行时使用应用 `.venv/Scripts/watcherobot.exe`（Windows）或 `.venv/bin/watcherobot`（macOS/Linux）的完整路径。不要依赖前一个 Shell 的变量或工作目录。已有项目使用原环境的 CLI。

Windows（替换为实际绝对路径）：
```powershell
& 'C:/应用父目录/my_robot_app/.venv/Scripts/watcherobot.exe' app run 'C:/应用父目录/my_robot_app'
```
macOS/Linux：
```sh
'/应用父目录/my_robot_app/.venv/bin/watcherobot' app run '/应用父目录/my_robot_app'
```
执行上述 run 之前完成下方状态检查。

1. 执行 `watcherobot daemon status` 和 `watcherobot robot status`。Daemon 未运行本身不是错误；`app run` 可以启动它。
2. 若已有 Daemon，查看状态中的 `runtime.sdk_version`、`runtime.build_id`、当前 application 和 device。与本地 SDK 不一致时先说明差异；不擅自停止 Desktop 或重启共享 Daemon。
3. 当前正在运行另一个应用且用户没有授权切换时，不执行 `app run` 接管；完成代码检查并告知需切换的具体应用。用户已授权切换或运行本项目时，继续，不重复索要同一授权。
4. 已连接目标机器人就复用。设备未连接且用户要真机运行时，让设备打开 **Python SDK** 应用。已有 Wi-Fi 不重置网络；由用户在本机终端使用 `watcherobot robot pair <当前六位码>`。配对码不写入代码、日志或交付文档。
5. 首次配网才使用交互式 `watcherobot robot setup`，用户按提示在本机输入 Wi-Fi 凭据，连接成功后再次 `robot status`。
6. 在应用目录执行 `watcherobot app run .`。不要执行 `python app.py`。查看日志和本能力的成功标准。

**退出预算：** 当前 Runtime 的普通停止最多等待 3 秒，然后可关闭通道并终止进程。`finish_thread` 会响应停止通知并尽力等线程结束，不能保证长调用的 finally 一定执行。持续循环检查 `app.shutdown_requested`；有会话句柄时在停止路径请求 cancel/stop，并验证释放。拍照等没有公开取消入口的调用若仍在途，记录“清理未确认”；需要完整结果时让单次任务正常完成。不要为掩盖问题把有效拍照预算强行缩短，也不要改共享 Daemon。

正常单次任务完成会退出；长期应用用 Ctrl+C 或 `watcherobot app stop` 停止**本次应用**。不要为了结束应用执行 `daemon stop`。`app start` 启动当前已选择应用；编辑新目录时使用 `app run <目录>`，不要混淆两者。

运行前调用关系：`用户界面 → Application → SDK → Daemon → 机器人`。Watcher Desktop 的业务消息由 Daemon 交给当前 Application；自建网页通过本应用自己的接口交互。不可添加 Desktop 绕过 Application 的设备业务通路。

## D07 错误处理：只做对应的一项修正

| 现象 | 执行操作 | 不要做 |
|---|---|---|
| Python 版本不支持 | 回 D01 换兼容解释器，重建本次新环境 | 忽略版本检查、破坏用户现有环境 |
| SDK 安装失败 | 记录索引/网络/依赖错误，修复可确认的问题后重试一次 | 静默改用不明同名包或 TestPyPI |
| `AttributeError`、方法或模板缺失 | 核对 D03 的模块路径和签名；在隔离环境检查用户指定的兼容安装包，更新前说明影响 | 凭版本号认定支持、拼接原始设备命令绕过 |
| 发布包仍无所需 API | 保留代码和明确的不可用提示；说明需含该接口的官方 SDK，可在用户指定来源后继续 | 猜一个最低版本号，自动切换开发分支 |
| `app_sdk_incompatible` | 安装满足清单且确实包含所需 API 的 SDK | 仅放宽清单假装兼容 |
| 已安装 SDK 与 Daemon 不一致 | 记录两边版本/build；需要重启或切换时说明被影响的运行应用 | 杀进程、停止用户正在使用的服务 |
| capability 不支持 | 说明所缺 capability；用户选择支持的方案，或另行处理固件升级 | 无条件调用、静默改变所选行为 |
| `not_found` | 核对实际资源目录、类型及 ID | 猜 `happy`、混用动画 ID 和行为 ID |
| `busy`、`no_capacity` | 停止并释放本应用持有的冲突会话，再重试一次 | 无限重试或并行启动更多媒体任务 |
| `camera_unavailable`、`executor_failed` | 确认连接；记录具体方法、设备返回错误和当前占用，检查视觉状态 | 直接宣称识别成功、改 Daemon 路由 |
| `storage_unavailable` | 检查设备 SD 存储；主机录制仅在设备支持且用户接受改变存储方式时选用 | 格式化 SD、删除用户资源 |
| 超时 | 记录等待的是命令、任务还是媒体；清理本应用资源，核对设备状态 | 将超时等同完成或已停止 |
| RTC 为 signaling / connecting | 继续媒体客户端的 SDP/ICE 和收流检查 | 将 start/ACK 当作音视频接通 |
| 云服务 401 / 403 | 检查供应商、凭据种类和账号权限；用户本机更新凭据 | 回显密钥、吞掉错误后返回假结果 |

排障需要的日志：保存方法名、超时值、错误码、SDK 路径/版本和 Daemon build，避免保存凭据与用户音视频内容。相同错误修正后再次失败就报告证据和缺少条件，不反复重装或重试。

## D08 仅在用户要求时发布

完整开发不依赖发布。发布前完成 app check，确认应用身份、平台声明和依赖；排除 `.venv`、缓存、照片、录音、日志与真实凭据。`.gitignore` 不等于发布过滤，需要检查 `.watcherignore`。

在授权的公开目标上，使用本项目 CLI：
```text
watcherobot app login --provider huggingface
watcherobot app publish . --provider huggingface
watcherobot app submit . --provider huggingface --commit <publish返回的完整commit>
```
用户指定 Gitee 时将 provider 统一替换为 `gitee`，先用相应命令 `--help` 确认本机支持。登录凭据在本机授权界面输入。`publish` 发布源码快照；`submit` 提交审核，二者都不代表已正式上架。已有明确发布授权就继续，不重复询问。
