# 首次动作冒烟测试

完成固件烧录和 SD 卡资源准备后执行本清单。目标是确认公开套装能够启动并执行一个可见行为，不代表完整验收。

## 准备条件

- 已下载最新 Release 中需要的附件
- 已烧录同一 Release 中的 STM32F103 固件
- 已使用同一 Release 的 `PTL-paired` ZIP 烧录 Himax 和 ESP32-S3
- 已使用同一 Release 的 `sd-resources` 压缩包准备 FAT32 SD 卡
- SD 卡根目录包含 `assets/`、`official_catalog.json` 和 `resource_manifest.json`
- 机器人已连接电源，并准备好串口监视工具
- 如需测试远程命令，已准备 BLE、WebSocket 或其他控制入口

先完成固件和 SD 卡步骤，再安装同一 Release 中的桌面端、移动端或 Python SDK 客户端。

## 启动检查

- ESP32 串口监视器能够打开正确端口。
- 启动日志进入应用启动流程。
- 屏幕完成初始化。
- 没有出现 SD 卡资源缺失错误。
- STM32 已连接时，MCU Link 会通过 `USART2 @ 921600 8N1` 尝试握手。
- PTL 摄像头进入预期的 Himax bridge 启动流程，且没有固件传输错误。

## 行为检查

| 检查项 | 通过标准 |
| --- | --- |
| 启动画面 | 屏幕显示启动或待机动画。 |
| 舵机动作 | 一条舵机命令在安全范围内完成动作。 |
| 灯效 | 静态或呼吸灯命令产生可见变化。 |
| 触摸事件 | 触摸产生日志或状态变化。 |
| BLE 或 WebSocket 命令 | 简单命令返回确认或产生可见状态变化。 |

如整机条件不完整，请记录跳过的项目和原因。

## 手工命令示例

通过 `USART1 @ 115200 8N1` 连接 STM32 本地 CLI 后：

```text
servo 1 90
ws red
ws off
```

执行舵机命令前确保机构活动范围安全。日志中不得包含 Wi-Fi 凭据、私人路径或其他敏感信息。

## 已知限制

- 本清单不能替代 CI 或完整硬件验收。
- 跨端协议覆盖仍需单独验证。
- 本清单仅适用于同一 Release 中一起发布的组件。
- 摄像头、视频、音频、方向和持续运行只有实机完成后才能标记为通过。
